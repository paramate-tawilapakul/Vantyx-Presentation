Feature Roadmap 2027–2028

แผน 2 ปีสำหรับ dev 1 คน จาก ข้อเสนอฟีเจอร์ใหม่ ครบทั้ง 18 ข้อ — ปี 2027 ผสมฟีเจอร์ทั่วไปที่คุ้มที่สุดกับ Local AI ตัวแรก, Local AI ที่เหลือครบภายใน Q2 2028 แล้วปิดด้วยงานด้านความเสถียรและคุณภาพ กดที่ฟีเจอร์เพื่อดูรายละเอียด

เหตุผล & KPI รายไตรมาส

ทำไมแต่ละข้ออยู่ในไตรมาสนั้น และจะวัดว่าได้ผลจริงอย่างไร — ควรเก็บ usage log ของแต่ละฟีเจอร์ตั้งแต่วันแรกที่ปล่อย

ไตรมาส ทำไมอยู่ช่วงนี้ วัดผลด้วย
2027
Q1Speed
  • งานเล็กที่ผู้ใช้ทุกคนเห็นผลทุกวัน → ได้ความเชื่อมั่นและ feedback เร็ว
  • 1.2 เป็นช่องทางแจ้งเตือนที่ 1.6 ใน Q2 ต้องใช้
  • 2.1 แบบ rule-based ได้ผลทันทีโดยไม่ต้องรอ GPU และเป็น baseline ไว้เทียบกับ LLM
  • เวลาเฉลี่ยตั้งแต่เปิดเคสจนถึง sign
  • จำนวนครั้งที่ใช้ shortcut / macro ต่อวัน
  • warning ที่ rule-based จับได้ และอัตรา addendum / co-sign decline (baseline)
Q2Control
  • 1.6 ส่งแจ้งเตือนผ่านช่องทางของ 1.2 ที่ทำเสร็จแล้ว
  • 1.4 ต่อยอด Report Editor จาก Q1
  • PoC ก่อนสั่งซื้อ GPU เพื่อไม่ให้ซื้อเครื่องผิด spec
  • % เคสที่ sign ทัน time guarantee แยกตาม modality / priority
  • % เคสที่เลือก template จากที่ระบบเสนอ
Q3AI
  • GPU ติดตั้งแล้ว → ทำ AI gateway กลางครั้งเดียว ใช้กับทุกฟีเจอร์ AI ต่อจากนี้
  • เริ่มจาก AI ที่เสี่ยงต่ำ: 2.1 เสริม LLM บน rule เดิม, 2.2 แค่เติมฟอร์มให้ผู้ใช้ตรวจก่อนกดค้น
  • อัตรา addendum / co-sign decline ก่อน–หลัง LLM
  • % ข้อเสนอของ AI ที่ผู้ใช้กดรับ (จาก log)
  • จำนวนครั้งที่ใช้ NL search ต่อวัน
Q4Follow-up
  • 2.3 ต้องมีรายการ follow-up ของ 1.8 จึงทำต่อกันในไตรมาสเดียว
  • ปิดช่องโหว่ด้านความปลอดภัยผู้ป่วย
  • % คำแนะนำ follow-up ที่ติดตามจนครบ
  • จำนวน follow-up ที่ AI ดึงได้และคนยืนยัน

Q3Reliability

สมมติฐาน & แผนสำรอง

สมมติฐาน

  • แรงพัฒนา (MD) ของแต่ละข้อใช้ตัวเลขเดียวกับ ข้อเสนอฟีเจอร์ใหม่; 2.1 แบ่งเป็น rule-based 8 MD + LLM 12 MD
  • dev 1 คน ≈ 40 MD ต่อไตรมาส: วันทำงานราว 60 วัน หัก support site, bug fix, QA และการลา ราว 1/3
  • 2 ปี ≈ 320 MD · แผนนี้ใช้ ≈ 302 MD — ปี 2027 แน่น (156 / 160) ปี 2028 มีที่ว่าง (146 / 160)
  • HTTPS และการจัดซื้อ GPU เป็นงานของทีม IT / จัดซื้อ ไม่นับ MD ของ dev
  • ทุกฟีเจอร์เปิด / ปิดต่อ site ผ่าน property ที่มีอยู่ — pilot 1 site ก่อนปล่อยทุก site
  • ฟีเจอร์ AI ทำงานต่อได้เมื่อ Ollama ล่ม และผู้ใช้ต้องกดยืนยันเสมอ

ถ้าแผนสะดุด

  • GPU server มาไม่ทัน Q3 2027 — สลับ Q3 กับ Q4: ทำ 1.8 ก่อน (ไม่ต้องใช้ GPU) แล้วค่อยทำ 2.1 + LLM, 2.2, 2.3 เมื่อเครื่องมา
  • ผล PoC ไม่ผ่าน — ยังไม่สั่งซื้อ GPU; 2.1 คงไว้ที่ rule-based และลองเปลี่ยน model / ขนาด model ระหว่างนั้นดึงฟีเจอร์ที่ไม่ใช้ AI จากปี 2028 ขึ้นมาทำ
  • ปี 2027 ล่าช้า — ใช้ที่ว่างใน Q3 2028 (≈ 12 MD) รับงานที่เลื่อนมา
  • dev ติดงาน support / งานด่วนจาก site — เลื่อน 1.5 / 1.9 / 1.10 ก่อน เพราะไม่มีข้ออื่นรอ
  • site ยังไม่เปิด HTTPS — 1.2 ใช้เสียง + ตัวเลขบน tab ไปก่อน popup ตามมาทีหลัง
